# 乡音心伴｜整体架构与团队开发文档

本文按本仓库现有代码整理，供前端、后端、算法同学分工协作。数据库表和已经部署的业务 API 路径保持不变。

## 项目主线

老人使用方言语音与乡音交流；系统把陪伴对话、心理量表筛查和家属/村协管员关怀跟进串成服务链。AI 可辅助转写、理解和表达，但不做心理诊断、不替老人作答；风险信号进入真人复核。

## 当前实际架构

React/TypeScript/Vite 前端部署到 Cloudflare Pages，调用 deploy/ 下的 Flask API（Cloudflare Python Workers）。Worker 验证 HMAC Bearer token，并通过 Hyperdrive 访问 Supabase PostgreSQL。Supabase 只提供数据库功能；当前登录演示不使用 Supabase Auth，也不调用 Supabase Edge Function。

| 层 | 当前实现 | 责任 |
|---|---|---|
| 前端 | React、TypeScript、Vite、React Router、Tailwind | 三角色页面、语音交互、量表体验、会话状态 |
| 身份 | Worker 演示登录签发 HMAC Bearer token | 当前比赛演示登录；不验证手机号归属 |
| 当前业务 API | deploy/app.py + Cloudflare Python Workers | token 校验、业务数据读写、算法编排 |
| 数据 | Supabase PostgreSQL，经 Cloudflare Hyperdrive 访问 | 沿用现有表结构与业务数据 |
| 预留服务 | supabase/ | 数据库迁移与种子；当前前后端不调用 Edge Function |
| 算法 | Worker 服务端及后续 provider adapter | 方言 ASR、陪伴回复、TTS、量表计分、风险辅助 |

## 前端、后端、算法分工

### 前端同学

- 页面在 frontend/src/pages，组件在 frontend/src/components。
- API client 在 frontend/src/lib/api.ts，Worker 认证会话在 workerAuth.ts，路由角色在 session.ts。
- 负责适老化 UI、语音采集/播放、逐题量表交互、请求状态、角色切换入口和 Pages 构建。
- 本地 xy_role 只控制界面路由，不是服务端授权凭据。

### 后端同学

- 当前前端业务 API 位于 deploy/app.py。
- 负责兼容 /api/...、校验 Worker 签名 token、沿用现有表执行数据读写和模型调用。
- Supabase Auth/Edge Function 不参与当前 API 链路；不得将 Supabase JWT 与 Worker token 混用。
- 数据库迁移须评审。本次角色切换只用现有 Auth 用户、profiles、elders、family_relations，不增加表。

### 算法同学

- 负责目标方言 ASR 评估、方言文本处理、陪伴回复策略、TTS、确定性量表计分和风险辅助。
- 经后端 adapter 接入，不直接写数据库、不信任客户端身份。
- 量表版本、题目、阈值和解释由心理/临床指导人员审核。LLM 不判题、不算分、不诊断。
- 提供模型/提示词版本、方言评测、延迟成本、失败策略和安全边界。

## 当前认证与 API

- 前端 API 根地址由 VITE_WORKER_API_URL 配置；api.ts 使用既有 /api/... 请求路径。
- 注册为 POST /api/register，之后 POST /api/demo-login 接受任意非空演示码并签发 Worker token。
- 当前用户为 GET /api/me，携带 Worker Authorization Bearer token。
- 演示角色切换通过登录到三个已注册的固定演示账号实现。
- 原有 /api/chat、/api/elders、/api/alerts、/api/care-messages、/api/family/... 等保持兼容。

## 关键数据流

### 方言陪伴

前端录音或识别 → 老人确认文本 → 通过既有聊天 API 提交 → Worker 校验会话和角色 → 模型回复或安全 mock → 保存必要记录 → 前端显示文字并可语音朗读。低置信度先确认，默认不长期保存原始录音。

### 量表筛查

前端逐题呈现专业人员审核的固定版本 → 用户确认答案 → 后端校验题目和选项 → 确定性规则计分 → 返回筛查提示和后续建议。现有 schema 没有量表会话、逐题答案、结果版本专表；需要持久化历史时先评审新增迁移，不复用情绪或病史字段。

### 风险关怀

规则/模型提供候选信号 → 服务端做权限和风险规则校验 → 写入现有 alerts → 家属/村协查看 → 真人处置、留言或转介。AI 输出仅为需关注提示，不是诊断。

## 演示安全开关

在线角色切换由 Pages 构建变量 VITE_DEMO_ROLE_SWITCH_ENABLED 控制，并切换到三个预先注册的演示账号。Workers 仍验证目标账号和角色；正式环境关闭该入口。

固定演示号码在 Pages 构建变量 VITE_DEMO_ELDER_PHONE、VITE_DEMO_FAMILY_PHONE、VITE_DEMO_VILLAGER_PHONE 中配置；账号必须先注册且 role 匹配。

浏览器不需要 Supabase key；Hyperdrive 凭据、DEMO_AUTH_SECRET、模型 key 仅存平台侧 secrets/bindings。禁止提交真实手机号、录音、答案和 token。

## 开发阶段和验收

1. 比赛闭环：三端、语音陪伴、量表体验和已有预警闭环可演示；在线切换角色后服务端会话也切换。
2. 算法验证：按目标方言评估 CER、风险短语召回、低置信度确认率和延迟；计分与人工样例一致。
3. 后续产品化：真实 OTP、量表历史迁移、权限审计、实时通知及音频删除策略。

模型失败时回退安全短回复；ASR 失败时允许文字输入；高风险提示真人跟进。量表筛查不等于临床诊断。
