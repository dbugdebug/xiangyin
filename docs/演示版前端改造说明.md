# 演示版前端改造说明（离线 Demo）

> 分支：`feat/demo-offline-frontend`　适用场景：比赛现场路演，**不依赖任何后端**。
> 代码改动位于 `frontend/`，本文档只做说明与验收记录。

## 1. 目标

1. 三端（老人 / 家属 / 村协）在**断网、无数据库**的环境下可完整演示。
2. 注册与登录**只做前端模拟**，不新增任何后端接口、API 请求、数据库操作或路由守卫。
3. 家属端 / 村协端**绝不暴露老人原始对话**，风险信息严格收敛到五个标准分类。
4. 老人端保持组员原版交互（点击式大麦克风按钮），仅移除顶部「一键呼叫家人」。

## 2. 改动清单

### 2.1 离线运行

| 文件 | 说明 |
| --- | --- |
| `src/config.ts` | `VITE_WORKER_API_URL` 默认值改为空字符串，三端默认走本地演示数据层 |
| `src/lib/api.ts` | 请求层在 base 为空时直接落到 `demoStore`，保留既有 `/api/...` 路径契约 |
| `src/lib/demoStore.ts` | 演示数据层：老人档案、预警、留言、处置记录、情绪趋势等 |

产物构建后 `index.html` 的 `<script type="module">` 可改为 `defer`，从而支持 `file://` 双击直接打开（`type="module"` 在本地文件协议下会被 CORS 拦截导致白屏）。

### 2.2 注册 / 登录：纯前端模拟

`src/pages/Login.tsx`、`src/pages/Register.tsx` 重写为三角色页签（老人 / 家属 / 村协管员），只做校验与前端跳转：

- 老人：姓名\*、密码\*、确认密码\*、手机号\*；（选填）年龄、性别、居住情况、所属村、住所位置、过往病史、紧急联系人；
- 家属：姓名\*、手机号\*、验证码、密码\*、确认密码\* —— 只做身份注册，**没有任何绑定老人入口**；
- 村协管员：家属字段 + 所属村镇（必填）；
- 验证码 60 秒倒计时、手机号 11 位校验、密码 ≥ 6 位且两次一致；
- 演示失败分支：`13800000001` ~ `13800000012` 为内置演示老人手机号，注册时提示"该手机号已注册"。

### 2.3 隐私：预警记录零原话 + 五分类结构化评估

**问题**：原预警卡片直接展示老人原话（如"对话中多次提到'活着没意思'"），存在隐私风险。

| 层面 | 处理 |
| --- | --- |
| 数据模型 | `AlertItem` 删除 `keyword`、`summary` 字段，改为 `category: RiskCategory`（只能是五个标准分类之一） |
| 评估逻辑 | 新增 `src/lib/assessment.ts`：按分类计数生成五维度评估 + 综合等级 |
| 展示组件 | 新增 `src/components/AlertRiskTag.tsx`：`风险类型：💗 情绪与自我价值 ｜ 状态：待处理` |
| 老人端上报 | `src/lib/risk.ts` 的 `RiskMatch` 只输出 `category`，`/api/risk-report` 只传 `category`，原话不出老人端 |
| 兜底收敛 | `asRiskCategory()` 把任何异常输入收敛到标准分类，绝不回退成原文 |

五分类（唯一可展示口径）：① 情绪与自我价值　② 家庭与社交适应　③ 健康与身体状态　④ 认知与安全风险　⑤ 经济与生活压力。

新增评估面板 `src/components/AssessmentPanel.tsx`，家属端整页展示、村协端点开老人详情弹层展示（同一口径）。

### 2.4 老人端

- 页面保持组员原版：顶栏 → 气泡对话流 → 底部 128px 大麦克风按钮（点一下说话、再点一下结束）+ `不方便说话？点这里打字` 兜底；
- **删除**顶部「📞 需要帮助？一键呼叫家人」按钮：HTML 块、`from-rose-500 to-orange-500` 等样式类名、`onClick` 与 `callOpen` 状态、`CallFamilyModal` 组件引用一并移除（`components/CallFamilyModal.tsx` 已删除）。

## 5. 接真实后端 / 大模型（本轮补充）

演示版**不再只跑本地假数据**：后端可用时前端自动走真实 `/api/*` 与 `/api/chat`（大模型对话），后端不可用时才回退本地演示数据，**画面与交互完全一致**。

### 5.1 后端地址怎么给

`src/config.ts` 解析顺序：

| 优先级 | 方式 | 场景 |
| --- | --- | --- |
| 1 | 构建变量 `VITE_WORKER_API_URL` | 固定部署（Cloudflare Worker / 固定后端域名） |
| 2 | 地址栏 `?api=http://192.168.1.5:5000`（记住到 localStorage，`?api=` 清除） | 路演临时换机器 / 换 IP，**不用重新构建** |
| 3 | 同源（页面由后端托管时） | 后端 `deploy/frontend_dist` 一体化托管 |
| 4 | 都没有（`file://` 双击） | 纯离线演示，走 demoStore |

推荐路演用法：把构建产物放进后端 `deploy/frontend_dist`，`python app.py`，浏览器打开 `http://<内网IP>:5000/` —— 同源、无 CORS、零额外配置。

### 5.2 鉴权：静默演示会话

后端 `before_request` 要求所有 `/api/**` 带 Bearer（仅 `/api/ping`、`/api/demo-login`、`/api/register` 放行）。演示版在 `workerAuth.ts` 新增 `ensureDemoSession()`：

1. 先 `POST /api/demo-login`（固定演示账号 `13800000001` → 种子库王桂兰）；
2. 账号不存在时先 `POST /api/register` 建号，再换会话；
3. 全程静默，不弹窗、不影响登录页（登录/注册仍是纯前端模拟）。

后端只需配环境变量（**不改后端代码**）：

```bash
AUTH_MODE=demo
DEMO_AUTH_SECRET=<任意随机串>
```

若后端不是 demo 模式（如 Supabase JWT），`ensureDemoSession()` 会失败并自动回退本地演示数据，页面照常可演。

### 5.3 数据接口对照

| 前端调用 | 后端路由 | 处理 |
| --- | --- | --- |
| `/api/stats`、`/api/screen-stats`、`/api/elders`、`/api/elders/:id`、`/api/referrals` | 同名 | 直接使用 |
| `/api/alerts` | 同名 | **丢弃 `keyword`/`summary`**（可能含老人原话），本地折算成五分类之一 |
| `/api/alerts/:id/handle`、`/api/care-messages`、`/api/activity`、`/api/mock-call` | 同名 | 直接使用 |
| `/api/risk-report` | 同名 | 只写标准分类文案（`keyword`/`summary` 两列填分类名），**不写任何原话** |
| `/api/assessment` | 后端未实现 | 用 `/api/elders/:id` + `/api/alerts` 在前端按同一口径现算 |
| `/api/chat` | 同名 | 真实大模型回复 + 数据库多轮记忆；风险由后端落库，前端只取分类 |

### 5.4 大模型

后端 `deploy/ai_service.py` 走 OpenAI 兼容接口，配环境变量即可（不改代码）：

```bash
AI_BASE_URL=https://api.deepseek.com/v1
AI_API_KEY=sk-xxxx
AI_MODEL=deepseek-chat
```

未配置或不可达时后端自动降级 mock 回复（响应 `offline: true`，气泡显示"网络开小差 · 演示回复"），现场不卡。

### 5.5 验证方式

本机实跑（SQLite + demo 鉴权）：

```bash
DB_MODE=sqlite AUTH_MODE=demo DEMO_AUTH_SECRET=xxx PORT=5000 python deploy/app.py
```

实测链路：页面加载 → 静默 `demo-login` 200 → `GET /api/stats|elders|alerts|care-messages` 200 → 老人端 `/api/chat` 200（回复 + 风险识别）→ 命中风险自动落库新预警。断开后端后刷新页面，自动回退 demoStore，界面无差异。
