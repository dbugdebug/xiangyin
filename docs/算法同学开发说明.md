# 乡音心伴｜算法同学开发说明

## 工作目标

围绕方言语音理解、老人友好陪伴、专业心理量表筛查和人工关怀闭环做可评估能力。算法不直接读写数据库，也不负责身份权限。

## 模块与实现边界

- ASR：方言转写、置信度和低置信度确认。
- 方言处理：保留地方词语原意，不能因普通话归一改变否定或时间信息。
- 陪伴回复：自然倾听、澄清、鼓励线下支持，不诊断、不建议药物。
- TTS：目标方言可懂度、语速和老人体验。
- 量表：专业人员确认版本后用确定性代码计分。
- 风险：透明规则优先、模型辅助发现、真人复核。

算法经 Worker 服务端 provider adapter 接入；可用 Python 做离线评测，线上调用托管 API 或独立推理服务。不要在 Worker 请求线程加载大模型。

## 方言语音评估

先明确具体方言点，使用知情同意的测试语料，覆盖年龄、语速和噪声环境。建立方言原文、普通话释义、专名和否定词的人工转写规范；避免同一说话人同时进入训练和测试。

报告 CER 字符错误率、关键风险短语召回与误报、老人修改识别比例、端到端延迟和失败率。按方言点/噪声分组并披露样本量。小样本只能称初步评估，不宣称临床准确率。

录音和心理信息按最小必要原则处理，明确用途、访问人和保留期限；不提交 Git 或普通日志。

## 陪伴安全

- 模糊语音先复述确认，不能把识别错误当事实。
- 不诊断、不提供未经审核的药物/治疗建议，不承诺绝对保密。
- 量表期间不诱导选项、不替老人作答。
- 疑似自伤/他伤表达用指导人员审核的话术提示联系真人，系统只生成复核信号。
- 固定回归案例覆盖否定句、引用他人、历史回忆、方言同音、重复表达和危机场景。
- 输出记录 provider、model_version、prompt_version、safety_flags；日志只保留非敏感元数据。

## 量表计分

量表版本、授权、适用人群、题目读法、阈值和解释由心理/临床指导老师确认。GDS-15 等只能作为候选。每个版本使用稳定 scale_id、question_id、option_id 和 scoring_version。

计分应为纯确定性函数；覆盖漏答、无效选项、反向题和边界分值，与人工样例逐项核对。程序和人工算分一致只证明实现一致，不代表临床效度。明确注明筛查不等于诊断。

当前数据库没有量表会话/答案/历史专表；表不变期间不把答案塞进 emotion_records 或病史字段。

## 交付和验收

- 目标方言、数据来源、知情同意与删除策略。
- ASR 指标、样本量、延迟和局限报告。
- 模型卡、调用成本、版本记录和降级方案。
- 量表版本审核记录及人工核算样例。
- 风险误报/漏报回归案例和真人复核流程。
- 比赛材料中能力声明与实际评测证据一致。
