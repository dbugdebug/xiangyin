# 乡音心伴｜后端同学开发说明

## 当前后端

前端当前 API 实现在 supabase/functions/api/index.ts（Deno + supabase-js）。服务端用 Supabase Auth 校验 JWT，从 profiles 获取 role/elder_id，再以 family_relations 验证家属访问。deploy/ 下 Flask + Cloudflare Python Worker/Hyperdrive 是备选实现；两类 token 不能混用。

## 数据库约束

表结构来自 supabase/migrations/20261013000100_create_xiangyin_schema.sql，包括 elders、profiles、family_relations、emotion_records、activities、alerts、care_messages、referrals；用户认证由 Supabase Auth 管理。本次不改表、不重复执行破坏性 SQL。

量表 session、逐题答案和历史结果专表尚不存在。要保存这些数据，先审查字段、权限、保留期限并评审新增迁移；不可复用情绪记录或病史字段。

## 新增演示角色切换

路径：POST /api/auth/demo/switch-role；浏览器 URL 为 SUPABASE_URL/functions/v1/api/api/auth/demo/switch-role。请求需带 apikey、Authorization Bearer 当前 Supabase access token、Content-Type，body role 为 elder/family/villager。

Edge Function 先验证已有 Supabase Auth 会话，再检查 DEMO_ROLE_SWITCH_ENABLED=true 和 FAKE_OTP_SECRET。然后为目标角色登录或创建固定演示账号，返回 {ok:true, session}。不更改当前账号的角色，不改 schema。

默认演示号码：老人 13800000001，家属 13900000001，村协管员 13900000002。可配置 DEMO_ELDER_PHONE、DEMO_FAMILY_PHONE、DEMO_VILLAGER_PHONE。家属演示账号通过现有 family_relations 绑定到演示老人。默认号与已有用户冲突时，使用专用号码，不得改动真实账号。

部署 Supabase Edge Function 时设置 DEMO_ROLE_SWITCH_ENABLED=true；已有 FAKE_OTP_SECRET 需保留，至少 32 个字符。可选设置三个演示号码作为 Function secrets。正式环境不要启用。

## 兼容和安全

- 既有 /api/... 路径和字段保持不变。
- 客户端 user ID/role/elder_id 不能代替 token 身份与服务端资源校验。
- service role 仅存在 Edge Function secrets；浏览器只使用 publishable/anon key。
- CORS allow headers 保留 authorization、apikey、content-type。
- 角色切换必须同时具备有效 Supabase 会话和显式开关。
- 日志不能输出手机号、完整对话、答案、音频或 JWT。
- Deno Edge 和 Flask Worker 的认证不可交叉使用。

## 算法边界

ASR/LLM/TTS 通过 adapter 接入，设置超时、request_id、provider/model 版本、结构化输出校验和降级。量表由确定性规则计分；LLM 不诊断、不判题、不代答。高风险信号进入真人复核。

## 发布验收

- 部署 Edge Function api 后，确认旧业务 API 仍可用。
- 演示环境设置 DEMO_ROLE_SWITCH_ENABLED=true；保留安全的 FAKE_OTP_SECRET。
- Pages 设置 VITE_DEMO_ROLE_SWITCH_ENABLED=true 并重新构建；正式环境关闭。
- 检查 OPTIONS、switch-role、返回 session、GET /api/me 及三角色授权。
- 备选 Flask Worker 单独验收，不要把 Supabase Auth session 传给其 demo token 认证。
