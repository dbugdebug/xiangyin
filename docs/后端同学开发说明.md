# 乡音心伴｜后端开发说明

## 当前后端

API 源码位于 `deploy/`：Flask + Cloudflare Python Workers。Supabase 只运行 PostgreSQL；Worker 使用 Cloudflare Hyperdrive 连接现有 Supabase 数据库。部署入口 `deploy/worker.py`，Wrangler 配置 `deploy/wrangler.toml`。

前端 Pages 请求 `VITE_WORKER_API_URL` 下的既有 `/api/...` 路由，Bearer token 由 Worker 签名。当前登录为演示验证码模式：`AUTH_MODE=demo`，Cloudflare Worker Secret `DEMO_AUTH_SECRET` 必须配置。不要把演示 token 与 Supabase Auth JWT 混用。

本地开发和部署：

    cd deploy
    uv sync --group dev
    uv run pywrangler dev
    uv run pywrangler deploy

如果从旧目录搬过虚拟环境，执行 `uv sync --reinstall --group dev` 重建启动器路径。

## 登录与注册

- `POST /api/register` 新建账号，写入现有 `"user"` 表；此路由无需登录。
- `POST /api/demo-login` 验证手机号、非空演示码、数据库账号和角色后签发 7 天 HMAC Bearer token。
- `GET /api/me` 验证 token，并按现有表初始化用户/老人档案或家属绑定。
- Worker 必须设 `AUTH_MODE=demo` 和 Secret `DEMO_AUTH_SECRET`；不要把 Secret 放入 `wrangler.toml`。
- 演示角色切换通过固定的三个已注册演示账号重新登录。号码在 Pages 的 `VITE_DEMO_*_PHONE` 设置。

假验证码不证明手机号所有权，只供演示。生产前要切换到真实 OTP 或安全的账号/密码流程，并加入限流、审计和资源级授权。

## 数据库约束

- 继续使用现有 Supabase PostgreSQL 表和字段。不要重复运行初始化脚本，不要直接修改线上 schema。
- Worker 的 `DB_MODE=postgres`，通过 Hyperdrive binding `HYPERDRIVE` 连接数据库；若返回表不存在，先核对 Hyperdrive 指向的项目，不要新建同名表绕过。
- 新增字段/表必须经维护者评审，以独立 migration 提交兼容和回滚说明。
- Supabase service role 和数据库凭据不放入浏览器环境变量或 Git。

## API、安全和算法接口

- 保持现有 `/api/...` 路径和响应契约，前后端同步改动并在 PR 标注。
- `Authorization` Bearer token 是后端身份来源；不能信任客户端传入的 user ID、role 或 elder_id。
- Flask-CORS 当前为跨域 API 配置；更改允许来源/请求头时，要覆盖 Pages 正式域名和 `authorization`、`content-type`。
- ASR/LLM/TTS 通过服务端 adapter 接入，设置超时、request_id、provider/model 版本和失败降级；API key 只存 Worker Secret。
- 量表采用经审核的确定性计分；LLM 不诊断、不判题、不代答。高风险提示进入真人复核。

## 发布检查

- 确认 `wrangler.toml` 的 Worker 名称、`DB_MODE`、`AUTH_MODE` 和 Hyperdrive ID。
- 确认 Cloudflare Secret `DEMO_AUTH_SECRET` 已设置且未发生意外轮换。
- 部署后检查 `/api/ping`，再通过页面验证 `/api/demo-login`、`/api/me` 和业务读写。
- 多端读写需确认 Worker 连接同一个 Supabase 项目/数据库。
