# 共享数据库注意事项（当前 Cloudflare 部署）

本文件已按当前后端重新整理。**部署步骤请看 [后端部署-Cloudflare-保姆级教程.md](后端部署-Cloudflare-保姆级教程.md)。**

## 数据库规则

- 线上后端使用现有 Supabase PostgreSQL，通过 Cloudflare Hyperdrive binding `HYPERDRIVE` 连接。
- 数据库结构保持现状：不要重新执行 `schema.sql`，不要 DROP/ALTER/TRUNCATE 任何表。
- 注册资料写入现有 `"user"` 表，手机号唯一；其他业务继续使用已有 `elders`、`alerts`、`care_messages` 等表。
- Cloudflare 配置必须保持 `DB_MODE=postgres`。缺少 Hyperdrive 会报错，不会自动换成本地 SQLite。
- 不要把 Supabase 密码、`AUTH_SECRET` 写入代码或提交仓库。Worker 的登录签名密钥通过 Cloudflare Secret 单独保存。

## 登录与验证码

当前 `/api/demo-login` 是假验证码演示模式：验证码框任意非空内容通过，不发送短信。该方式仅供当前演示联调。登录成功后服务端签发 HMAC Bearer token，前端随后调用 `/api/me`；无需更改已部署前端的 API URL。

## Supabase 连接目标

Hyperdrive 必须指向建有本项目现有表的 Supabase 项目。检查 Hyperdrive 配置时核对数据库、用户名和端口；不要把密码发到聊天或文档。如果 `"user"` 不存在，优先检查是否连错项目，不要通过新建同名表绕过。

## 排错需要提供什么

若接口 500，去 Cloudflare **Workers & Pages → xiangyin-xinban-api → Logs → Real-time Logs**，复制对应请求的完整 Python traceback，并附上请求路径和时间。不要只凭浏览器的 `Failed to fetch` 判断原因。
