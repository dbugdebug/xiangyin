# 乡音心伴｜前端同学开发说明

## 代码和技术栈

前端源码在 frontend/，采用 React、TypeScript、Vite、React Router 和 Tailwind，部署到 Cloudflare Pages。页面在 src/pages，共用组件在 src/components，API client 在 src/lib/api.ts，认证在 src/lib/supabaseAuth.ts，路由角色在 src/lib/session.ts。

## API 与登录态

API 根地址来自 VITE_SUPABASE_URL，路径为 /functions/v1/api；继续按既有 /api/... path 调用。浏览器仅使用 publishable/anon key，不得放服务端 key。

- 演示登录：POST /api/auth/demo；验证码任意非空，不发短信。
- 登录态：GET /api/me，携带 Supabase access token。
- 业务调用经过 api.ts。线上权限由服务端 JWT/profile 校验决定；localStorage 的 xy_role 不能作为授权依据。

## 在线演示角色切换

现有 RoleSwitch.tsx 在本地 mock 模式只切 UI。Supabase 配置存在时，VITE_DEMO_ROLE_SWITCH_ENABLED=true 才显示在线切换入口。按钮调用 supabaseAuth.ts 的 switchDemoRole，请求 POST /api/auth/demo/switch-role。

成功后将新 session 写入现有认证存储，更新 elder_id 和 UI role，并导航到对应首页。失败时保留原角色并显示错误。不要只 setRole() 后进入其他线上角色端。

启用需要两端开关：Pages 构建变量 VITE_DEMO_ROLE_SWITCH_ENABLED=true，且 Edge Function secret DEMO_ROLE_SWITCH_ENABLED=true。生产环境关闭。

## 页面交互

- 老人端使用大字、高对比、大点击区域；录音状态、停止键和文字输入路径明确。
- ASR 低置信度时让老人确认文本；TTS 失败仍显示文字。
- 量表逐题呈现、可朗读、可返回/暂停；前端不算最终心理结论。
- 家属和村协页面的数据由后端授权；路由守卫只是 UI 体验。
- 请求头改动需和 Edge Function CORS 配置同步。

## 验收

- [ ] 本地 mock 模式角色切换保持原行为。
- [ ] Supabase 配置下开关关闭时不显示在线切换。
- [ ] 两端开关开启且登录后，可以切换三种固定演示身份。
- [ ] 成功后刷新仍保持新会话，并进入匹配角色首页。
- [ ] 服务端拒绝或断网时角色不变且显示错误。
- [ ] 正式 Pages 构建默认不启用角色切换。
- [ ] 弱网、401/403、录音拒绝、空数据和模型降级有明确反馈。

日志不打印 token、手机号、病史、量表答案或完整聊天。离线只缓存静态资源，不缓存心理答案和原始录音。
