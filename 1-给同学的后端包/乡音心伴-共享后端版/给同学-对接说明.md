## 〇、三句话讲清楚

1. 我们两个的后端**各写各的、各自部署，互不依赖**，但**连同一个云数据库**（Supabase PostgreSQL）。
2. 你的 MySQL 代码**不能直接用**，需要把数据库写法换成 PostgreSQL 的（本文第五章有对照表，15 条）。
3. **建表不用你做**，我已经建好了（11 张表）。你只要改代码 + 填 `.env` + 连上就行。

> 💡 **这份代码支持两种数据库模式**，用 `.env` 里一个开关切换，业务代码完全不用改：
>
> | `DB_MODE` | 数据库 | 用途 |
> |---|---|---|
> | `sqlite`（不填时的默认） | 项目自带的本地文件 | 一键部署、纯演示，零配置 |
> | `postgres` | Supabase 云库 | **我们两个共用同一个库**（你要用的就是这个） |
>
> 你现在要做的，就是把 `DB_MODE` 设成 `postgres`。

## 五、⚠️ 代码改动对照表（照着改你自己的代码）

你的 MySQL 代码里凡是出现**左列**写法，就换成**右列**。**逻辑不用改，只改写法。**

| # | MySQL 写法 | PostgreSQL 写法 |
|---|---|---|
| 1 | `import mysql.connector` | `import psycopg2` / `import psycopg2.extras` |
| 2 | `mysql.connector.connect(host=..., user=..., password=...)` | `psycopg2.connect(host=..., user=..., password=..., dbname=..., sslmode='require')` |
| 3 | `INT AUTO_INCREMENT PRIMARY KEY` | `SERIAL PRIMARY KEY` |
| 4 | `` `user` `` / `` `elders` ``（反引号） | `"user"` / `"elders"`（**双引号**） |
| 5 | `ENUM('a','b')` | `VARCHAR(20) CHECK (col IN ('a','b'))` |
| 6 | `TINYINT(1)` | `BOOLEAN` 或 `SMALLINT` |
| 7 | `DATETIME` / `TIMESTAMP` | `TIMESTAMP` |
| 8 | `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4` | **整段删掉** |
| 9 | `cursor.lastrowid` | `INSERT ... RETURNING id` 然后 `cur.fetchone()['id']` |
| 10 | `ON DUPLICATE KEY UPDATE ...` | `ON CONFLICT (字段) DO UPDATE SET ...` |
| 11 | `IFNULL(a, b)` | `COALESCE(a, b)` |
| 12 | `DATE_SUB(NOW(), INTERVAL 7 DAY)` | `NOW() - INTERVAL '7 days'` |
| 13 | `CURDATE()` | `CURRENT_DATE` |
| 14 | `FIELD(x,'a','b')` | `CASE x WHEN 'a' THEN 1 WHEN 'b' THEN 2 END` |
| 15 | `GROUP_CONCAT(x)` | `STRING_AGG(x, ',')` |

### 5.1 ⚠️ 三个最容易出错的写法

**① `user` 是 SQL 保留字，必须加双引号；但 Python 引号会打架**

```python
# ❌ 错：Python 会报语法错误（双引号冲突）
cursor.execute("SELECT id FROM "user" WHERE phone = %s", (phone,))

# ✅ 对：外层用单引号包住含双引号的 SQL
cursor.execute('SELECT id FROM "user" WHERE phone = %s', (phone,))
```

**② 想用 `row['id']` 取值，必须指定字典游标**

```python
import psycopg2.extras

cur = conn.cursor()                                                  # 返回元组，只能 row[0]
cur = conn.cursor(cursor_factory=psycopg2.extras.RealDictCursor)     # ✅ 返回 dict，可 row['id']
```

> 你原来的 MySQL 代码如果用 `cursor(dictionary=True)`，**全部换成上面的 `cursor_factory` 写法**。

**③ 占位符不用改**

`%s` 在 MySQL 和 psycopg2 里**一样**，这块不用动。（只有 SQLite 才用 `?`）

### 6.2 `POST /api/register` 详细说明

**请求体**：

```jsonc
{
  "name": "张三",
  "password": "abc123456",
  "confirm_password": "abc123456",   // 必填，两次必须一致
  "phone": "13700001111",            // 11 位，1 开头
  "role": "elder",                   // elder | family | villager，不传默认 elder
  "village": "后山村",                // 仅 villager 必填
  "age": 75,                         // 选填
  "gender": "男",                    // 选填，只能 男/女
  "medical_history": "高血压",        // 选填 → 写入 health_profile 表
  "ec_name": "张小",                 // 选填 → 写入 emergency_contact 表
  "ec_phone": "13700002222"          // 选填
}
```

**成功响应**（HTTP 201）：

```json
{ "ok": true, "user_id": 1, "role": "elder", "message": "老人账号注册成功" }
```

**失败响应**：

- `400` 校验失败：`{"ok": false, "message": "两次输入的密码不一致"}`
- `409` 手机号已注册：`{"ok": false, "message": "该手机号已注册，请直接登录"}`

**⚠️ 注意这个接口的约定和别的不同**：
注册/绑定用 **HTTP 状态码**表达成败（201/400/409）；
而 `/api/chat`、`/api/stats` 等业务接口是「**HTTP 200 + `{ok:false}`**」。
前端 `registerAccount()` 依赖 `res.ok` 判断，所以**状态码不能改**。

## 七、⚠️ 必须遵守的三条约定

### 7.1 `"user"` 表结构以这份为准（不要自己改）

```sql
CREATE TABLE "user" (
    id            SERIAL PRIMARY KEY,
    name          VARCHAR(50)  NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    phone         VARCHAR(20)  NOT NULL UNIQUE,
    role          VARCHAR(20)  DEFAULT 'elder',   -- elder / family / villager
    village       VARCHAR(50),                    -- 所属村镇（仅村协管员）
    age           INTEGER,
    gender        VARCHAR(10),
    created_at    TIMESTAMP    DEFAULT CURRENT_TIMESTAMP
);
```

**`role` 字段很重要**：前端注册页三种角色共用，取值只有：

- `elder` —— 老人
- `family` —— 家属
- `villager` —— 村协管员（**同时必须填 `village`**）

**要加字段可以，但先告诉我**，别自己 `ALTER TABLE`，否则两边对不上。

### 7.2 密码存储方式必须统一

我用的是 **`werkzeug.security.generate_password_hash` / `check_password_hash`**（scrypt 哈希）。
如果你打算用别的（bcrypt / md5 / sha256），**先跟我说**，否则我这边无法验证你注册的账号。

### 7.3 别动 `elders` 表，别 `DROP TABLE`

- `elders`（老人档案）是我这边的核心表，你绑定老人时**只读不改结构**
- 需要关联就通过 `elder_binding` 表
- **绝对不要 `DROP TABLE` 或 `TRUNCATE`**，那会把我这边一起搞崩
- 测试数据随便造，我会定期清理

## 八、常见报错速查

| 报错信息 | 原因 | 解决 |
|---|---|---|
| `tenant/user "postgres" not found` | `DB_USER` 填成了 `postgres` | 改成 `postgres.mbwycygpdtvwyungzrbr` |
| `password authentication failed` | 密码错 | 找我要正确密码 |
| `could not connect to server: Connection timed out` | 用了直连地址（IPv6） | 换成带 `pooler` 的地址 |
| `ModuleNotFoundError: No module named 'psycopg2'` | 没装驱动 | `pip install psycopg2-binary` |
| `relation "user" does not exist` | 表名没加双引号 | 改成 `"user"` |
| `column "xxx" does not exist` | 表结构和假设不一致 | 参考本文 7.1 的表定义 |
| `syntax error at or near "ENGINE"` | 建表语句没改 | 删掉 `ENGINE=InnoDB ...` 那段 |
| `column "id" of relation ... does not exist` | 用了 `lastrowid` | 改用 `RETURNING id` |
| `SSL connection is required` | 没开 SSL | `.env` 里 `DB_SSLMODE=require` |
| `terminating connection due to administrator command` | Supabase 免费版 7 天不活跃自动暂停 | 去 Supabase 控制台唤醒（随便打开一下项目页） |
| 浏览器访问 localhost 连不上 | 系统代理拦截了本地请求 | 给 `localhost;127.0.0.1` 加代理例外，或 `curl --noproxy '*'` |
