## 一、最隐蔽的坑：确认你连的真是云库

代码里有个开关 `DB_MODE`。这是**最容易出错、而且错了还看不出来**的地方：

| 你的 `.env` 写法 | 实际行为 | 后果 |
|---|---|---|
| `DB_MODE=postgres` ✅ | 连 Supabase 共享云库 | 正常，两边数据互通 |
| `DB_MODE=sqlite` ❌ | 写进你自己电脑的本地文件 `xiangyin.db` | **注册接口返回"成功"，但我这边完全查不到这个账号** |
| 不写 `DB_MODE`，且 `DB_HOST` 是远程地址 | 自动判定为 postgres | 正常 |
| 不写 `DB_MODE`，且 `DB_HOST` 空/localhost | 自动判定为 sqlite | 同上，数据进本地文件 |

**怎么自证连对了**：启动时控制台会打印一行

```
[DB] 当前数据库模式: PostgreSQL（aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres）
```

看到 `PostgreSQL` 才对。看到 `SQLite` 就说明你连的是本地文件，数据没有进云库。

> 另外：如果你机器上没装 `psycopg2`，程序会自动降级成 SQLite 并打印一段警告 —— 这时注册照样"成功"，但数据没进云库。看到警告就装驱动：
> `pip install -r requirements-postgres.txt`

## 二、连接信息（照抄，别猜）

```ini

DB_HOST=aws-0-ap-southeast-1.pooler.supabase.com
DB_PORT=5432
DB_USER=postgres.mbwycygpdtvwyungzrbr     # ← 必须带 “.项目编号”，不能只写 postgres
DB_PASSWORD=（找我要）
DB_NAME=postgres
DB_SSLMODE=require
```

三个必踩的坑：

1. `DB_USER` 必须是 `postgres.项目编号`，只写 `postgres` 会报 `tenant/user "postgres" not found`
2. `DB_HOST` 必须用带 `pooler` 的地址，直连地址（IPv6）会超时
3. `DB_SSLMODE` 必须 `require`，否则报 `SSL connection is required`

**连上自测**（先做这一步，别写完代码才试）：

```bash
python -c "
import psycopg2, os
from dotenv import load_dotenv; load_dotenv()
c = psycopg2.connect(host=os.getenv('DB_HOST'), port=os.getenv('DB_PORT'),
                     user=os.getenv('DB_USER'), password=os.getenv('DB_PASSWORD'),
                     dbname=os.getenv('DB_NAME'), sslmode='require')
cur = c.cursor()
cur.execute('select count(*) from \"user\"'); print('user 表行数 =', cur.fetchone()[0])
cur.execute('select count(*) from elders'); print('elders 表行数 =', cur.fetchone()[0])
"
```

预期：`elders` 一定是 **12 行**（内置演示老人）。如果报 `relation "user" does not exist`，说明连的不是我们这个库。

## 四、`"user"` 表结构以这份为准（唯一权威）

```sql
CREATE TABLE "user" (
    id            SERIAL PRIMARY KEY,
    name          VARCHAR(50)  NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    phone         VARCHAR(20)  NOT NULL UNIQUE,
    role          VARCHAR(20)  DEFAULT 'elder',   -- elder / family / villager
    village       VARCHAR(50),                    -- 所属村镇（仅村协管员）
    age           INTEGER,                        -- 老人端选填
    gender        VARCHAR(10),                    -- 老人端选填
    created_at    TIMESTAMP    DEFAULT CURRENT_TIMESTAMP
);
```

**三条铁律：**

1. **`role` 只有三个取值**：`elder`（老人）/ `family`（家属）/ `villager`（村协管员），别自己发明第四个
2. **要加字段可以，先告诉我** —— 我这边也要同步加，否则我的接口读不到你的数据
3. **不要自己 `CREATE TABLE`** 同名表，也不要用 `IF NOT EXISTS` 假装建表 —— 结构以本文件为准

⚠️ 线上库的列顺序可能和我贴的略有不同（当初 `role`/`village` 是用 `ALTER` 补上去的，会被追加到末尾）。**列名、类型完全一致，只是顺序不同**，写 SQL 时按列名访问即可，**不要用 `INSERT INTO "user" VALUES (...)` 这种不带列名的写法**。

## 五、必须和我说一声的 3 件事

### 5.1 密码哈希算法要统一

我用的是 **`werkzeug.security.generate_password_hash` / `check_password_hash`**（scrypt）。

```python
from werkzeug.security import generate_password_hash, check_password_hash

# 存储
password_hash = generate_password_hash(form['password'])
# 校验
ok = check_password_hash(row['password_hash'], form['password'])
```

如果你用 bcrypt / md5 / sha256，**你注册的账号我这边的登录接口验不过**。要换算法先商量。

### 5.2 自增主键的取法（PostgreSQL 没有 `lastrowid`）

```python
# ❌ MySQL 写法：cursor.lastrowid   →  PostgreSQL 下没有这个属性
# ✅ PostgreSQL 写法：
cur.execute('INSERT INTO "user" (name, password_hash, phone, role, village) '
            'VALUES (%s, %s, %s, %s, %s) RETURNING id',
            (name, pwd_hash, phone, role, village))
new_id = cur.fetchone()[0]
```

### 5.3 表名 `user` 是关键字，必须加双引号

```sql
SELECT * FROM "user" WHERE phone = %s;   -- ✅
SELECT * FROM user   WHERE phone = %s;   -- ❌ 报语法错误
```

## 六、方言对照：你的 MySQL 代码改过来只需改这几处

| MySQL 写法 | PostgreSQL 写法 |
|---|---|
| `` `user` `` 反引号 | `"user"` 双引号 |
| `INT AUTO_INCREMENT` | `SERIAL` |
| `TINYINT(1)` | `SMALLINT` |
| `ENUM('a','b')` | `VARCHAR(20) CHECK (x IN ('a','b'))` |
| `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4` | 删掉 |
| `IFNULL(x, '')` | `COALESCE(x, '')` |
| `FIELD(a,b,c)` | `CASE WHEN ... END` |
| `GROUP_CONCAT(x)` | `STRING_AGG(x, ',')` |
| `DATE_SUB(CURDATE(), INTERVAL 7 DAY)` | `CURRENT_DATE - INTERVAL '7 days'` |
| `ON DUPLICATE KEY UPDATE` | `ON CONFLICT (...) DO UPDATE SET` |
| `cursor.lastrowid` | `INSERT ... RETURNING id` |
| `%s` 占位符 | `%s`（psycopg2 一样，不用改） |

## 七、共用库的「社交礼仪」（真的会踩）

| 事项 | 说明 |
|---|---|
| **事务要短** | 拿到连接→查询→`commit()`→**尽快归还连接**。别在事务里等待用户操作，会把连接池占满 |
| **异常必须 `rollback()`** | 出异常不 `rollback`，连接会带着脏事务回到池里，之后所有请求都可能报错 |
| **唯一约束冲突要捕获** | `phone` 是 UNIQUE。并发注册同一手机号时数据库会抛 `UniqueViolation`，要捕获并返回 **409**，不要让它变成 500 |
| **不要 `DROP TABLE` / `TRUNCATE`** | 有一方的数据在里面，删了不可恢复（免费版没有自动备份） |
| **不要跑 `init_db.py`** | 那是 MySQL 版建表脚本。建表用 `schema.sql`（已经建好了，正常也不用再跑） |
| **不要大范围 `DELETE`/`UPDATE` 不带 `WHERE`** | 演示数据清理请找我，我统一处理 |
| **注意时区** | `created_at DEFAULT CURRENT_TIMESTAMP` 存的是 **UTC 时间**（Supabase 服务器时间），前端展示若要北京时间需 +8 |
| **免费版会休眠** | 项目 7 天无访问会自动暂停，报 `terminating connection...`，去 Supabase 控制台打开项目页唤醒即可 |

## 十、出问题了怎么办

先别自己改结构。把下面这些发我，我这边能直接定位：

1. 报错完整堆栈（不要只发一句"连不上"）
2. 启动时那行 `[DB] 当前数据库模式: ...` 日志
3. 你执行的 SQL 或接口调用（`curl` 命令 / 请求体）
4. 你期望的结果 vs 实际结果

最常见三类问题的快速自查：

| 现象 | 大概率原因 |
|---|---|
| 我这边查不到你注册的账号 | 你连的是本地 SQLite，不是云库（回到第一节） |
| `column "xxx" does not exist` | 表结构和第四节的不一致，或列名写错 |
| `relation "user" does not exist` | 表名没加双引号，或连错库 |
