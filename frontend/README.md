# 乡音心伴 · AI 语音陪伴 App 原型（路演 Demo）

> 让每一位农村老人，都有人说话、有人关心、有人守护。
> 面向农村老人的方言 AI 语音陪伴产品：老人用语音和大模型唠嗑，系统在对话中**轻量嵌入情绪与抑郁筛查**，发现风险自动预警并转介家属 / 村协管员，形成"筛查 — 预警 — 转介 — 闭环"。

> 当前线上结构为 Cloudflare Pages + Cloudflare Workers API + Supabase PostgreSQL。Supabase 只提供数据库；手机号演示认证和业务 API 由 Worker 提供。

---

## 快速开始

```bash
npm install
npm run dev
```

打开终端提示的地址即可（默认 `http://localhost:5173`）。**建议用 Chrome / Edge**：语音识别需要浏览器支持。

> 若 5173 被其他项目占用，可换端口：`npm run dev -- --port 5175 --strictPort`
> Vite 已开启 `--host`，电脑与手机连同一 WiFi，手机访问 `http://<电脑IP>:端口` 可**真机体验语音**。

**本 Demo 默认使用本地演示数据（纯前端 mock），无需启动任何后端服务**，打开即有 12 位老人、三档风险、历史预警与处置记录可演示。

### 不想装 Node 环境？直接看静态包

如果你或组员电脑没有 Node，可解压 `xiangyin-prototype-dist-*.zip`，在 `dist` 目录执行：

```bash
npx serve
```

或

```bash
npx http-server -p 8080
```

然后浏览器打开 `http://localhost:8080` 即可。

> ⚠️ 因为浏览器安全策略（CORS），**不要直接双击 `index.html` 用 `file://` 协议打开**，否则会白屏。用任意静态文件服务器（`serve` / `http-server` / nginx / VS Code Live Server 等）都可以。

## 一、三个角色端怎么演示

### 1. 登录 / 选身份

打开首页即登录页，「您是哪一位？」用**大卡片点选**：

| 角色 | 首页路由 | 说明 |
| --- | --- | --- |
| 👴 老人 | `/chat` | 语音对话主页（超大按钮、超大字号） |
| ❤️ 家属 | `/family` | 亲情守护看板 |
| 🧑‍🌾 村协管员 | `/village` | 全村网格化管理工作台 |

- 点 **「🚶 一键进入体验（演示模式）」** 免登录直达所选角色的首页（路演最快路径）；
- 也可填手机号 + 任意验证码点「登录」，同样按角色跳转。

### 2. 三端之间切换（路演专用）

每个已登录角色端右上角有「🎭 切换演示角色」。本地 mock 模式只切换本地角色；Worker 在线模式下会重新登录到 Pages 环境变量中配置的固定演示账号，并保存 Worker 签名会话。

在线切换需将前端构建变量 VITE_DEMO_ROLE_SWITCH_ENABLED=true，并在 VITE_DEMO_ELDER_PHONE、VITE_DEMO_FAMILY_PHONE、VITE_DEMO_VILLAGER_PHONE 配置已注册的专用演示账号。正式环境关闭。更多部署配置见仓库根目录 DEPLOY.md。

### 3. 角色权限守卫

角色信息存 `localStorage`。直接手改地址栏越权访问（如老人角色访问 `/village`）会被守卫拦回登录页，并提示「当前角色无权限」。

## 二、路演主线动线（核心叙事，建议照此演示）

> 这条链路**端到端真实打通**：老人端说消极话 → 预警写入共享数据流 → 家属端与村协端**立刻看到红色预警** → 处置后**风险等级下调、待处置数减少**。

| 步骤 | 操作 | 现场看到什么 |
| --- | --- | --- |
| ① | 登录页选 **👴 老人** → 一键进入 | 进入语音对话主页 |
| ② | 点底部「⌨️ 不方便说话？点这里打字」，输入 **`我不想活了，活着没意思`** 发送（语音同理） | 乡音温柔安抚；**技术侧触发【风险预警】** |
| ③ | 右上角 🎭 → 切到 **❤️ 家属端** | 风险预警区**置顶出现红色预警**（命中词 + AI 摘要），亲情卡片状态变「需关注」，可点「📞 一键回拨」「✓ 标记已处理」 |
| ④ | 右上角 🎭 → 切到 **🧑‍🌾 村协管员端** | 「待处置预警数」+1；**🚨 预警看板**里出现该老人（高风险红标）；点「⚡ 今日需关注」已在清单里 |
| ⑤ | 在预警看板点一条处置动作（如「📞 电话回访」），或点老人进详情用**处置闭环表单**填写处置说明后提交 | 预警变「已处理」、写入处置记录、**老人风险等级自动下调一档（红 → 黄 → 绿）**，返回总览可见「待处置预警数」减少、花名册色带**由红变黄** |

补充演示点：

- **家属主动关怀**：家属端「远程关怀」点「💊 提醒吃药」或写留言 → 切到老人端，乡音会主动说"家里人给您捎了个话…"（真实注入下一轮对话上下文）。
- **筛查统计**：村协端「📋 筛查统计」看筛查完成率与三档风险占比。
- **转介记录**：村协端「🏥 转介记录」查看已转介名单；处置时选「建议转介乡镇卫生院」会自动新增一条转介记录。
- **导出**：村协端右上「⬇️ 导出关注名单」下载 CSV（红 + 黄老人清单）。

## 三、三端功能一览

### 老人端 `pages/Chat.tsx`（核心页，保持原有实现）

- 顶部：乡音头像 + 按时段问候 + 角色标签 + 切换身份 / 退出；
- 中部：气泡对话流（老人居右暖橙、AI 居左带头像），AI 回复带「🔊 播放 / ⏹ 停止」重播；
- 底部：**超大圆形麦克风按钮**，录音时呼吸 + 双层波纹动画；
- 一轮对话**四态分别提示**：聆听中 🎤 → 识别中 ⏳ → 生成中 💭 → 播放中 🔊；
- 常驻 **「📞 需要帮助？一键呼叫家人」** 醒目入口（求助 / 转介）；
- 语音不可用时自动提供打字兜底，**每轮对话静默上报活跃度与风险**（演示动线入口）。

### 家属端 `pages/FamilyDashboard.tsx`

1. **亲情卡片**：老人头像、姓名、年龄、方言片区、独居/留守、绑定关系、上次通话时间、当前情绪标签、「已 X 天未说话」呼吸提醒、一键回拨；
2. **今日陪伴概况**：今日对话轮次 / 陪伴时长 / 活跃时段 / 是否多日未活跃（大数字 + 短标签）；
3. **AI 陪聊小结**：一句话概括本周情绪与主要话题；
4. **近 7 天情绪温度计**：纯 CSS 柱状，暖黄（平稳）→ 暖红（低落），点击柱子看当天摘要；
5. **远程关怀**：语音问候 / 提醒吃药喝水 / 写留言一点即达，回车后提示「将于下次通话时由乡音转达」；「📞 今日提醒我打电话」开关（浏览器 Notification 模拟）；
6. **风险预警记录**：倒序展示，含触发时间、命中风险词、AI 摘要、状态标签（待处理 / 已处理），提供**一键回拨**与**标记已处理**；
7. **对话摘要**：列表 + 点击展开**脱敏气泡回放**；
8. **联系村协管员**入口，形成家属 ↔ 村协联动。

> 🔒 **隐私与尊严设计（答辩加分点）**：家属端**只展示 AI 生成的情绪与话题摘要**，不提供老人的完整逐字对话记录。页面底部有明确说明，可直接回应「数据伦理与老人尊严」类提问。

### 村协管员端 `pages/VillageBoard.tsx`

1. **工作总览四统计卡**：在册老人总数 / 今日活跃人数 / 待处置预警数 / 高风险人数（大字 + 状态色）；
2. **老人花名册**：卡片式，按风险从高到低排序，左侧色带**红（高风险）/ 黄（关注）/ 绿（平稳）**；显示姓名、年龄、独居留守、最近情绪、最近活跃时间、待处置条数；
3. **筛选与搜索**：风险等级、**今日是否对话**、居住状态、方言片区、姓名搜索；「⚡ 今日需关注」一键只看红 + 黄；
4. **方言片区分布**：片区人数标签，点击即筛选；
5. **🚨 全村预警看板**：集中展示全村预警，支持**按严重程度 / 按时间**排序，每条可直接快捷处置（电话回访 / 上门探访 / 转介卫生院 / 继续观察）；
6. **单人详情**：情绪趋势 + 全部预警记录 + **历史处置记录**（谁、何时、做了什么）+ 处置闭环表单；
7. **处置闭环（灵魂功能）**：处置方式可选电话回访 / 上门探访 / 已联系家属 / 建议转介乡镇卫生院 / 暂不处置需继续观察，填写处置说明 → 提交后预警转「已处理」、**老人风险等级自动下调一档**、写入处置记录；
8. **📋 筛查统计**：筛查完成率进度条 + 三档风险占比色条 + 本周新增风险；
9. **🏥 转介记录**：老人 / 转介对象 / 时间 / 状态表格；
10. **⬇️ 导出关注名单 CSV**（原型级实现）。

## 四、数据说明（重要）

**全部数据来自本地演示数据层 `src/lib/demoStore.ts`，纯前端、零后端、零网络请求。**

- 12 位老人：红 3 / 黄 4 / 绿 5；含 3 位独居高龄（≥80 岁）；2 位连续 3 天以上未活跃；
- 6 条预警样例（含 2 条「已处理」并带处置记录）、9 条脱敏对话摘要、4 条转介记录、近 7 天情绪曲线；
- 三端共用**同一份数据 + 同一个预警数据流**（模块级单例 + 发布订阅）：
  `老人端命中消极表达 → reportRisk() 新增预警并置红 → 家属端 / 村协端同步可见 → handleAlert() 转已处理并下调风险`。

> 说明：本项目为**纯前端原型**，不包含任何后端服务，也不需要数据库。
> 数据访问统一走 `src/lib/api.ts`（`api.get / api.post`，REST 风格路径）；
> 将来若需接真实后端，只需把该文件里的 `mockRoute` 换成 `fetch`，**页面代码零改动**。

## 五、接入真实大模型（OpenAI 兼容接口）

`chat()` 会先用 **1.5 秒极短探测**判断模型服务是否在线：

- **探测到** → 走真实大模型；
- **探测不到**（现场没装模型 / 没网）→ 立即使用本地 mock 温情回复（气泡带"网络开小差"小标签），**不卡住、不白屏**。

### 方式一：本地 Ollama（零成本）

1. 安装 [Ollama](https://ollama.com) 并拉取模型：

   ```bash
   ollama pull qwen2.5:7b   # 或 llama3
   ```

2. **关键一步——允许跨域（CORS）**，否则浏览器请求会被拦截：
   - Windows：`setx OLLAMA_ORIGINS "*"`，然后**重启 Ollama**（托盘退出再启动）；
   - macOS / Linux：`OLLAMA_ORIGINS=* ollama serve`
3. 重启 `npm run dev`，打开页面时会自动探测到 Ollama 并用它对话。

> 路演提示：本地模型冷启动首次回复可能要十几秒，建议开场前先"预热"一句，并保持模型常驻（`OLLAMA_KEEP_ALIVE=30m`）。

### 方式二：DeepSeek / 硅基流动等在线服务

复制 `.env.example` 为 `.env`，改成对应服务：

```bash
# 硅基流动 SiliconFlow
VITE_API_BASE_URL=https://api.siliconflow.cn/v1
VITE_API_MODEL=Qwen/Qwen2.5-7B-Instruct
VITE_API_KEY=sk-xxxxxxxx

# 或 DeepSeek
# VITE_API_BASE_URL=https://api.deepseek.com/v1
# VITE_API_MODEL=deepseek-chat
# VITE_API_KEY=sk-xxxxxxxx

# 完全不使用大模型（纯 mock 回复）
# VITE_LLM_ENABLED=0
```

改完 `.env` 重启 `npm run dev` 生效。

> 风险预警的触发：真实模型的 System Prompt 已约定"出现明显消极/绝望信号时在回复最前面加【风险预警】"；前端会提取该标记并上报（界面上不显示标记）。同时前端还有**本地关键词兜底筛查**（`lib/risk.ts`），保证演示时必定触发。

## 八、设计与实现说明

- **技术栈**：React 18 + Vite 5 + TypeScript + Tailwind CSS 4 + React Router 7；移动端优先（375–430px），桌面端居中预览，看板页多列栅格铺满。
- **适老化（老人端）**：正文 ≥20px、触控目标 ≥48px、暖橙配色、零复杂层级、重要操作 2 步内到达；不支持语音的浏览器自动提供打字兜底。
- **工作台可读性（家属端 / 村协端）**：信息密度适度提高，但最小字号 ≥16px、触控目标 ≥44px、状态色对比充足；风险色用暖红 / 琥珀 / 青绿三色，避免刺目纯红，预警标记"一眼可见"。
- **一轮对话四态**：聆听中 🎤 → 识别中 ⏳ → 回复生成中 💭 → 播放中 🔊，状态条与按钮动画分别提示，绝不合并成"加载中"。
- **语音**：识别用 Web Speech API（`lang=zh-CN`）；朗读用 `speechSynthesis`（自动挑中文音色、语速 0.9），每条 AI 回复可随时重播。
- **安全人设**：system prompt 要求乡音"温柔、说大白话、多共情、**绝不做医学诊断**、绝不推荐药物"，老人流露强烈负面情绪时先安抚并引导家人关心。
- **健壮性**：纯前端零依赖运行；大模型不可用 → mock 温情回复；数据层任何异常 → 友好占位可一键重试；任何环节都不白屏、不报错。
- **隐私**：纯前端原型，数据不上传；家属端只给脱敏摘要，不给逐字对话。
